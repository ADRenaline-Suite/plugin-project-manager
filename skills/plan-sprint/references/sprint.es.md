# Plan del sprint

Fuente: Scrum Guide, 2020. El Sprint Planning deja el Sprint Goal, los ítems elegidos y el plan para entregarlos. Quien va a hacer el trabajo lo dimensiona. Este archivo no lo dimensiona. El tipo de archivo es `sprint`.

## Qué fija

Para qué vale este periodo, qué trabajo entra y cómo se va a entregar.

## Cómo hacerlo

1. La meta del sprint es una frase que un interesado puede leer. Si existe un resultado accepted de `plugin-product` y la persona ata la meta a ese archivo, cítalo. No escribas el resultado.
2. El periodo es el inicio y el fin que dio la persona, o la duración que dio. No inventes fechas.
3. Los ítems elegidos son nombres que dio la persona, o archivos que este plugin ya escribió (un caso de uso, una tarea, un backlog). No añadas un ítem.
4. El plan de entrega apunta a una tarea entre repositorios ya escrita, o registra el plan que dijo la persona. No descompongas el trabajo en pasos de implementación y no estimes un tamaño.
5. Un ítem que aún no tiene archivo se queda como nombre. Di que el archivo falta. No escribas ese archivo en este turno, salvo que también lo hayan pedido.

## Plantilla

Encabezados, en este orden. Tradúcelos.

## Meta del sprint

obligatorio. Para qué vale este sprint.

## Periodo

obligatorio. El lapso. Si la persona no dio uno, este encabezado es el hueco.

## Ítems elegidos

obligatorio. Cada ítem por nombre o por archivo.

## Plan de entrega

obligatorio. El archivo de la tarea entre repositorios, o el plan que dijo la persona. Sin estimación.

## Done

- Los cuatro encabezados están, en este orden, en el idioma del pedido.
- No se inventó un ítem, una fecha, un resultado ni una estimación. Un resultado de producto es una cita, no un párrafo copiado de ese plugin.
- El estado es `accepted` solo cuando la meta, el periodo y al menos un ítem elegido vinieron de la persona. Un periodo que falta o una selección vacía es un hueco y el archivo queda `proposed`.
